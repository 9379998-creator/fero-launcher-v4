# Bridge: эксперт <-> локальный агент

Ветка `bridge` - канал обмена. Код проекта живёт в `main`, здесь только задания и результаты.
Репозиторий ПУБЛИЧНЫЙ: не выводить и не коммитить секреты (.env, токены, пароли, ключи).

## Роли
- Эксперт (Perplexity) пишет задания в `.agent_bridge/inbox/NNN-название.md`.
- Агент (локальный) выполняет и пишет результат в `.agent_bridge/outbox/NNN-название.md`.
- Владелец проекта только говорит каждому: "bridge".

## Что делает агент по слову "bridge"
1. Не трогать рабочую папку `main`. Использовать отдельный worktree:
   `git fetch origin bridge` затем `git worktree add ..\fero-bridge bridge` (если уже есть: `git -C ..\fero-bridge pull --ff-only`).
2. Взять в `inbox/` задание с наибольшим номером, для которого ещё нет файла в `outbox/`.
3. Выполнить ровно то, что написано в задании. Ничего сверх. Если что-то не совпадает с описанием (контекст патча, номера строк) - остановиться и описать расхождение в результате.
4. Записать результат в `outbox/NNN-название.md` по формату ниже.
5. `git add .agent_bridge/outbox` -> commit `bridge: result NNN` -> `git push origin bridge`.

## Правила
- Режим задания указан в строке `mode:` - `read-only` или `apply`.
- В режиме `read-only` ничего не менять, выводить текст ДОСЛОВНО (с номерами строк), без пересказа и сокращений.
- В режиме `apply` менять код только в рабочей папке `main`, отдельным коммитом на каждый пункт, `git push origin main` только если в задании написано `push: yes`. Никогда `--force`.
- Не запускать команды, которых нет в задании. Не запускать сервер.
- Не выводить содержимое `.env`, токенов, ключей, паролей.
- Вывод команд - в блоках кода, перед каждым: `### команда` и код возврата.

## Формат результата (outbox)
```
# Result NNN
status: ok | partial | failed
branch/commit: <hash>
## Что выполнено
- пункт: ok/failed (причина)
## Вывод команд
### команда (exit code)
<дословный вывод>
## Расхождения
- ...
```
