## 2. Раздел A: Архитектурный аудит существующего экспортёра и точек вызова

### 2.1. Точки входа и сквозной стек вызовов
1. **Клиентский захват рамки и координат (`app/frontend/lib/pdfjs/web/launcher-translate.js:660–697`):**
   - Прямоугольная зона `zoneBox` пересчитывается из экранных пикселей DOM в типографские пункты страницы PDF:
     ```javascript
     const scale = (pageView.viewport && pageView.viewport.scale) || (pRect.width / (pageView.width || pRect.width)) || 1.0;
     const x0 = Math.min(rx0, rx1) / scale;
     const y0 = Math.min(ry0, ry1) / scale;
     const x1 = Math.max(rx0, rx1) / scale;
     const y1 = Math.max(ry0, ry1) / scale;
     pdfCrop = [x0, y0, x1, y1];
     ```
   - Запрос отправляется на бэкенд: `POST /api/pdf/export-cad` с полями `{ file, page, crop }`.
2. **Маршрутизация бэкенда (`app/backend/server.py:3892–3915`):**
   - Эндпоинт `/api/pdf/export-cad` парсит аргументы, нормализует `crop_box` в кортеж float и вызывает `export_pdf_page_to_cad(...)`.
3. **Основной модуль экстракции (`app/cad/pdf_cad_extractor.py:72–460`):**
   - Класс `PDFCadExtractor.extract_cad(page_number, crop_box, output_path, options)`.

### 2.2. Пошаговый разбор этапов `pdf_cad_extractor.py` (доказано кодом)
1. **Адаптивный Padding рамки (`lines 117–121`):**
   ```python
   cx0 = max(0.0, cx0 - crop_pad) # crop_pad = 14.0 pt (~4.94 мм)
   cy0 = max(0.0, cy0 - crop_pad)
   cx1 = min(page_rect.width, cx1 + crop_pad)
   cy1 = min(page_rect.height, cy1 + crop_pad)
   filter_rect = fitz.Rect(cx0, cy0, cx1, cy1)
   ```
   *Факт:* Рамка расширяется на 14 пунктов, но элементы, пересекающие эту границу, жестко отсекаются по фильтру `filter_rect.intersects(d["rect"])` без присвоения флага неполноты детали.
2. **Извлечение графики через PyMuPDF (`lines 125–127`):**
   ```python
   all_drawings = page.get_drawings()
   drawings = [d for d in all_drawings if filter_rect.intersects(d["rect"])]
   ```
   *Факт:* `get_drawings()` возвращает список словарей со свойствами `rect`, `items`, `fill`, `color`, `width`, `dashes`, `closePath`.
3. **Детекция масштаба по тексту (`lines 130–146`):**
   ```python
   m_scale = re.match(r"^1[/:](\d+(\.\d+)?)$", txt)
   if m_scale:
       denom = float(m_scale.group(1))
       if denom > 0:
           scale_factor_detected = denom
   ```
   *Факт:* Масштаб вычисляется исключительно по регулярному выражению на изолированных словах. Если на чертеже нет надписи вида `1:1` или `1:2`, масштаб слепо принимается равным 1.0 без проверки по выносным линиям размеров.
4. **Сэмплирование сплайнов Безье (`lines 33–42, 192–201`):**
   ```python
   def sample_bezier(p1, p2, p3, p4, steps=8):
       ...
   ```
   *Факт:* Все кубические кривые Безье (оператор `c`) делятся на жестко фиксированные 8 хорд, независимо от радиуса скругления или кривизны.
5. **Сборка сегментов и затягивание штриховок (`lines 179–218`):**
   - Все отрезки `l`, аппроксимированные кривые `c` и прямоугольники `re` складываются в единый массив `raw_segments`.
   - *Критический дефект:* Границы заполненных областей (`fill is not None`, в том числе 928 элементов черного заполнения и градиентных штриховок каталога) не изолируются, а их граничные отрезки попадают в общую кучу `raw_segments` наравне со стенками профиля.
6. **Жадная сшивка полилиний (`Polyline Chaining`, lines 220–276):**
   - Используется жадный поиск по списку `unused` с допуском `chain_tol = 0.5 pt` (~0.176 мм).
   - Сшиваются любые сегменты, чьи концы оказались ближе 0.5 pt, без учёта топологии узлов (T- и Y-образных развилок), ориентации нормалей и физической принадлежности деталей.
7. **Преобразование координат и инверсия Y (`lines 278–288`):**
   ```python
   ox = filter_rect.x0
   oy = filter_rect.y1
   total_scale = PT_TO_MM * scale_factor_detected
   cad_x = (pt[0] - ox) * total_scale
   cad_y = (oy - pt[1]) * total_scale
   ```
   *Факт:* Начало координат переносится в левый нижний угол обрезанной зоны. Ось Y инвертируется (в CAD вверх положительное направление).
8. **Эвристическая классификация по слоям (`lines 356–386`):**
   - Пунктир (`is_dashed`) -> `08_ОСИ`.
   - Отрезки между стрелками -> `07_РАЗМЕРЫ`.
   - Диагональные отрезки `abs(dx - dy) < 0.25` или пространственный диапазон X `tb_min_x <= avg_x <= tb_max_x` при числе точек `< 15` -> `03_ТЕРМОМОСТ`.
   - Все остальные контуры -> `01_АЛЮМИНИЙ_РАМА`.
   *Факт:* Никаких проверок реальных замкнутых сечений, полостей, сборок или разделения наружной/внутренней чаши нет. Группировка в CAD-блоки (`BLOCK`/`INSERT`) отсутствует.

## 6. Точная локализация потери структуры (Root Cause Analysis)

Потеря структуры сечений происходит в трёх конкретных местах алгоритмического конвейера:

1. **`app/cad/pdf_cad_extractor.py:179–218` (Затягивание штриховки в рабочий контур):**
   - Векторный PDF содержит тысячи объектов `fill`, представляющих плотную заливку полиамида, вспененного уплотнителя (HI+) и декоративных теней. Код извлекает все отрезки этих заливок в единый пул сегментов, не отделяя граничные контуры деталей от внутренней штриховки.
2. **`app/cad/pdf_cad_extractor.py:220–276` (Жадный сшивщик Polyline Chaining):**
   - Алгоритм обходит сегменты по первому попавшемуся совпадению концов в радиусе 0.5 pt. На любом T-образном или Y-образном стыке (внутреннее ребро жесткости, камера винтового канала, зуб закатки термомоста) алгоритм сворачивает на внутреннее ответвление. Дойдя до тупика, он останавливает полилинию, оставляя основной внешний периметр разорванным навсегда.
3. **`app/cad/pdf_cad_extractor.py:373–386` (Разрушение деталей наивной эвристикой слоёв):**
   - Пространственный фильтр по координате X жестко режет детали на границах 40% и 85% ширины. Полилинии одного и того же профиля произвольно раскидываются между слоями `01_АЛЮМИНИЙ_РАМА` и `03_ТЕРМОМОСТ` на основании числа точек (`< 15`), полностью уничтожая сборку.

## 7. Обоснованные инженерные допуски для будущей реализации

На основе выполненных измерений эталонной геометрии MasterLine 8 предлагаются следующие нормативные допуски:

1. **Допуск соединения вершин контура ($\varepsilon_{\text{chain}}$):** **`0.025 мм`** (0.07 pt).
   - *Обоснование:* В исходном векторе PyMuPDF координаты вершин одного непрерывного пути совпадают с точностью до 0.005–0.015 мм. Допуск выше 0.05 мм недопустим, так как толщина зазора под закатку лапы термомоста составляет 0.20–0.30 мм, а толщина тонких лепестков уплотнителей — 0.40–0.60 мм. Сшивка с порогом 0.18 мм неизбежно стягивает противоположные стенки тонких пазов.
2. **Допуск адаптивной аппроксимации кривых Безье ($\delta_{\text{chord}}$):** **`0.010 мм`** (10 мкм).
   - *Обоснование:* Вместо фиксированного шага `steps=8` разбиение должно выполняться рекурсивно (алгоритм де Кастельжо) до тех пор, пока максимальное расстояние от хорды до дуги не станет $\le 0.01$ мм. Это сохранит гладкость сопряжений пазов без раздувания числа вершин.
3. **Допуск поиска дубликатов и наложенных сегментов ($\varepsilon_{\text{dup}}$):** **`0.005 мм`**.
   - *Обоснование:* Сегменты с совпадающими координатами и противоположным направлением (возникающие на границах смежных заливок в PDF) должны взаимно уничтожаться до начала сшивки.
4. **Фильтрация микро-элементов штриховки:**
   - Замкнутые полигоны заливки с габаритом $< 0.8$ мм по одной из осей или площадью $< 0.5$ мм² исключаются из структурного графа профиля.
